# План обновления

## Для чего этот справочник

Шпаргалка по вопросам с собеседований для фронтенд-разработчика. Ей пользуюсь я
и мои коллеги. Три сценария, под которые всё оптимизируется:

1. **Освежить знания** перед собеседованием.
2. **Отвечать, поглядывая краем глаза.** Страница должна читаться с одного
   взгляда: коротко, одна тема на страницу, списки вместо абзацев. С этим
   текущий формат уже справляется хорошо — его нельзя сломать.
3. **Собеседовать других**, имея перед глазами эталонный ответ и вопросы
   «вглубь».

Это в первую очередь текст. Интерактив (тренировочный режим, запускаемые
примеры) — возможный задел на будущее, сейчас не планируется.

## Принятые решения

- **Движок:** остаёмся на Docusaurus. Переезд на Astro Starlight рассмотрен и
  отклонён: упереться не во что, а тренировочный режим на React потом проще
  сделать здесь.
- **Менеджер пакетов:** pnpm. Bun отклонён: Docusaurus поддерживает его только
  как установщик пакетов, рантаймом остаётся Node.
- **Границы контента:** развиваем фронтенд и React Native. SQL и Node.js
  остаются в текущем минимальном объёме — только исправление ошибок.
- **Next.js Page Router:** остаётся (ещё востребован), но сжимается.
- **Старые URL не сохраняем:** при переездах, слияниях и удалениях страниц
  редиректы не делаем.

## Порядок

Стек → аудит → глобальная структура → правка разделов → пробелы. Структура
раньше вычитки, чтобы не вычитывать страницы, которые потом будут слиты,
перенесены или удалены.

## Этап 2. Глобальная структура

Готово. Страницы разложены по списку из [AUDIT.md](AUDIT.md) («Входные данные
для этапа 2»); карта «старый путь → новый» — там же, в разделе «После этапа 2».
Текст страниц при этом не правился: слияния — это склейка с выравниванием
уровней заголовков, убраны только прямые повторы. Вычитка — этап 3.

Разделы:

| Группа   | Раздел          | Что внутри                                                      |
| -------- | --------------- | --------------------------------------------------------------- |
| Основное | `javascript`    | плюс сборка мусора из `common`                                  |
|          | `typescript`    | без изменений, кроме переименования                             |
|          | `css`           | новый; пока одна страница про подходы к стилизации              |
|          | `web-platform`  | бывший `browser` плюс отладка, бандл, хранилища, аутентификация |
|          | `react`         | подгруппы `basics` / `hooks` / `performance` / `ecosystem`      |
|          | `nextjs`        | Page Router сжат с 10 страниц до 4                              |
|          | `react-native`  | папка `other` → `release` («Build and Release»)                 |
| Общее    | `programming`   | принципы кода, парадигмы, паттерны, алгоритмы                   |
|          | `tooling`       | тесты, пакетные менеджеры, CI/CD, ревью, методологии            |
|          | `git`           | 3 страницы                                                      |
| Смежное  | `nodejs`, `sql` | только исправление ошибок                                       |

Решения, принятые по ходу:

- `common` разобран на `programming` и `tooling`; раздела `common` больше нет.
- В навбаре «Общее» и «Смежное» — выпадающие списки General и Related: 12
  разделов в одну строку не помещаются. На главной «Смежное» — отдельный блок.
- `web-platform` пока плоский. Подгруппы (безопасность, производительность,
  доступность) появятся на этапе 4 вместе со страницами — группа из одной
  страницы только мешает.
- Event loop в JavaScript и Node.js не слит (поправка из аудита).
- У новых разделов нет своих иконок: `css` и `tooling` показывают общую.

Шаблон страницы — [docs/\_template.md](docs/_template.md) (Docusaurus не
публикует файлы с `_` в начале имени):

- заголовок — вопрос или термин, как его называют на собеседовании;
- сразу под заголовком эталонный ответ в 2–4 предложения или короткий список,
  ключевые термины выделены; всё до первого `##` — это и есть короткий ответ;
- `## Details` и `## Example` — подробности и запущенный пример кода;
- `## Follow-up Questions` и `## Common Mistakes` — блок для интервьюера;
- по желанию: уровень в `tags` (`junior` / `middle` / `senior`) и строка
  `Applies to: …` с версией библиотеки.

Фиксированные названия секций и граница «до первого `##`» — задел под
тренировочный режим: его можно будет построить поверх контента без
переписывания. К шаблону страницы приводятся на этапе 3.

## Этап 3. Правка разделов

Вычитка всех страниц по таблицам из [AUDIT.md](AUDIT.md). Правило: **правим, а
не переписываем.** Страница не должна вырасти в объёме без причины.

Решения:

- **Граница с этапом 4.** Существующие страницы с вердиктом «переписать» и
  «дополнить» (включая `generics` и `caching`) делаются здесь. Из колонки «Не
  хватает» берётся только то, без чего страница не отвечает на свой вопрос. Всё,
  что тянет на отдельную страницу, — этап 4.
- **Шаблон.** Обязательны короткий ответ до первого `##` и фиксированные
  названия секций. `Follow-up Questions` и `Common Mistakes` пишутся только там,
  где материал уже есть в аудите. Справочные страницы (`arrays`, `sql/commands`)
  остаются справочными, с коротким ответом сверху.
- **Версии.** `Applies to: …` — последняя стабильная версия на момент правки
  раздела, сверенная с документацией.
- **Орфография.** Американская (Optimization), проверка cspell в CI.
- **SQL.** Все примеры на PostgreSQL, оговорено на странице раздела.

Порядок, по одному PR на шаг:

- [ ] 0. cspell в CI, опечатки и американская орфография по всем разделам.
- [ ] 1. JavaScript.
- [ ] 2. TypeScript (поднят перед React по итогам аудита).
- [ ] 3. React.
- [ ] 4. Web Platform.
- [ ] 5. Next.js.
- [ ] 6. React Native.
- [ ] 7. `programming`, `tooling`, `git`, `css`.
- [ ] 8. `nodejs`, `sql` — только ошибки.

Что входит в правку раздела:

- ошибки и устаревшее из колонки «Ошибки» аудита;
- каждый изменённый пример кода запущен, язык блока соответствует содержимому;
- страница приведена к шаблону, следы генерации текста и вода убраны;
- `sidebar_position` по порядку, без дублей и дыр;
- перекрёстные ссылки между связанными страницами;
- правила markdownlint MD029 и MD036 (отключены на этапе 0) включены для
  раздела.

Разделение работы по моделям. Писать в один раздел одновременно может только
один агент.

| Работа                                                                                                                          | Модель |
| ------------------------------------------------------------------------------------------------------------------------------- | ------ |
| Механика: опечатки, `sidebar_position`, язык блоков, MD029 / MD036, точечные правки, для которых в аудите записан готовый ответ | Sonnet |
| Содержание: «переписать» и «дополнить», короткие ответы, ошибки по существу, сверка версий с документацией                      | Opus   |
| Запуск примеров кода                                                                                                            | Sonnet |
| Проверка фактов перед PR — свежим агентом, который не видел хода правки                                                         | Opus   |

В каждом разделе: механический проход → правка содержания → запуск примеров и
проверка фактов → PR.

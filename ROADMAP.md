# План обновления

## Для чего этот справочник

Шпаргалка по вопросам с собеседований для фронтенд-разработчика. Ей пользуюсь я
и мои коллеги. Три сценария, под которые всё оптимизируется:

1. **Освежить знания** перед собеседованием.
2. **Отвечать, поглядывая краем глаза.** Страница должна читаться с одного
   взгляда: коротко, одна тема на страницу, списки вместо абзацев. С этим
   текущий формат уже справляется хорошо — его нельзя сломать.
3. **Собеседовать других**, имея перед глазами эталонный ответ и вопросы
   «вглубь».

Это в первую очередь текст. Интерактив (тренировочный режим, запускаемые
примеры) — возможный задел на будущее, сейчас не планируется.

## Принятые решения

- **Движок:** остаёмся на Docusaurus. Переезд на Astro Starlight рассмотрен и
  отклонён: упереться не во что, а тренировочный режим на React потом проще
  сделать здесь.
- **Менеджер пакетов:** pnpm. Bun отклонён: Docusaurus поддерживает его только
  как установщик пакетов, рантаймом остаётся Node.
- **Границы контента:** развиваем фронтенд и React Native. SQL и Node.js
  остаются в текущем минимальном объёме — только исправление ошибок.
- **Next.js Page Router:** остаётся (ещё востребован), но сжимается.
- **Старые URL не сохраняем:** при переездах, слияниях и удалениях страниц
  редиректы не делаем.

## Порядок

Стек → аудит → глобальная структура → правка разделов → пробелы. Структура
раньше вычитки, чтобы не вычитывать страницы, которые потом будут слиты,
перенесены или удалены.

## Этап 1. Аудит

Готово: результат в [AUDIT.md](AUDIT.md), там же сводка и поправки к этапам 2–4.

Одна таблица на все страницы, без правок текста: вердикт (оставить / переписать
/ слить с… / удалить / перенести), актуальность, найденные ошибки, чего не
хватает. Результат — входные данные для этапов 2–4.

## Этап 2. Глобальная структура (черновик)

- Разобрать `common` на осмысленные части.
- Добавить разделы CSS и Web Platform (безопасность, производительность,
  доступность, хранилища); `browser` влить туда.
- SQL и Node.js — в группу «смежное».
- Page Router сжать с 10 страниц до 3–4.
- Слить дубли (тестирование в трёх разделах, event loop в двух), избавиться от
  страниц `other.md`.
- Зафиксировать шаблон страницы:
  - заголовок — вопрос или термин, как его называют на собеседовании;
  - сверху эталонный ответ в 2–4 предложения или короткий список, ключевые
    термины выделены;
  - затем подробности и пример кода;
  - внизу блок для интервьюера: уточняющие вопросы, частые ошибки в ответах;
  - по желанию — пометка уровня (junior / middle / senior).

Единообразная разметка «вопрос → короткий ответ → детали» — это и есть задел под
тренировочный режим: его можно будет построить поверх контента без
переписывания.

## Этап 3. Правка разделов (черновик)

При правке раздела вернуть правила markdownlint MD029 и MD036, отключённые на
этапе 0, чтобы не трогать контент.

По одному разделу на PR: JavaScript → React → TypeScript → Browser → Next.js →
React Native.

Правило: **правим, а не переписываем.** Страница не должна вырасти в объёме без
причины. Заглушки дополняем, нормальные страницы только чистим от ошибок и
устаревшего, приводим к шаблону и связываем перекрёстными ссылками.

## Этап 4. Пробелы (черновик)

Новые страницы по списку из аудита. Уже видно, что не хватает: промисы и
async/await, модули, generics и utility types, CSS, безопасность (XSS, CORS,
CSP), Web Vitals, доступность, Web Storage и воркеры.
